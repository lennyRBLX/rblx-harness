# Delegated work

Prefer subagents when a concrete split improves speed or output quality with efficient total token use. Handle small edits and settings tweaks directly unless complexity or risk warrants delegation.

- For large tasks, maintain a small reusable team across research, implementation, testing, optimization and review; add agents only as needed. Give each agent a stable role in a coherent domain. Bound assignments by scope, owned paths and symbols, inputs, contracts, permissions and expected result.
- Use `researcher` for unresolved contracts and `debugger` while a failure's cause is unknown. `implementer` can combine scoped project research, writing and affected checks for one owner.
- Reuse existing agents for related follow-ups. Keep role instructions stable; append assignments, changes and evidence to preserve useful, cacheable history. Start fresh when stale or unrelated context outweighs reuse benefits.
- For delegated features, GUI changes, fixes and implementation plans, keep `optimizer` and `reviewer` independent of implementation. Run `optimizer` after implementation or drafting, resolve its findings, then run `reviewer` with that disposition. Preserve read-only role limits and disabled nested delegation. Source and plan assessment can use static evidence. For plans, assess dependencies, authority, lifecycle and acceptance.
- Each path has one writer per worktree. Preserve other agents' edits. Run independent scopes in parallel and sequence dependencies and conflicting writes. The primary owns shared files and Git mutations. Continue useful work while agents run and wait for needed results. Use separate worktrees for independent chats.
- Concurrent writers reserve assigned scopes once with `coord begin` and validate tokens with `coord check --lease` before mutation. Existing assignments supply scopes and owner/parent IDs. `coord end` releases completed work; native hooks release ended agents/sessions. Expiry stays unknown. Integration reuses a current `inspect diff --overlap` result until relevant inputs change. See [tool fields](../../../../TOOLS.md#evidence).
- Share exact paths, APIs, literals, restrictions, open questions and valid findings/checks with their scope and revisions. Reuse valid work and rerun only affected or required checks. Return changed paths, concise findings with references, check results and blockers. Omit raw logs.
- Use permitted models and reasoning suited to task difficulty; reserve costly settings for demanding work. Preserve configured role profiles and inherit session settings where unspecified. For setting changes or comparisons, read [models.md](models.md).
- Judge total completion time, quality and cost across all agents, including retries; do not optimize cache-hit rate alone.

Codex subagents inherit the parent turn's permissions. Apply role instructions and configured tool limits, and verify effective sandbox permissions when isolation matters. [Codex subagent permissions](https://learn.chatgpt.com/docs/agent-configuration/subagents#approvals-and-sandbox-controls)
